# MXGA 功能回归

## 测试前

日常和发布前默认增量，从[脚本用例](tests/script/README.md)和[文本用例](tests/text/README.md)选例去重。

- **冒烟**选受影响功能最短的基本流程，例如改复制时先复制一条短帖。
- **迭代必测**默认选普通回复翻译往返 `GROK-01` 和搜索折叠原文复制 `COPY-03`。同一迭代可引用后续改动未影响的实测结果，验收时补齐。
- **变更点**测本次行为、相关边界和共享代码的调用入口。例如短链解析改动同时测点击和复制。

按用户指定的范围执行。要求某项功能覆盖所有页面时，逐页验证该功能。明确要求项目全测时，覆盖全部用例及本次变更点。仅改文档时核对规则、命令和链接。

以本次需求定义通过条件，沿用其余已确认的预期。AI 用已确认样本或 X 原生行为作对照，仍有歧义再问用户。

Chrome 实测复用已连接的 `my-chrome`、登录账号和[样本入口](references/samples.md)。验证工作区改动前重载本地扩展，来源为 `UNPACKED`。验证商店版指定 `MXGA_TEST_SOURCE=FROM_STORE`。来源不符或多份扩展同时启用时，将受影响用例记为未验证，保留用户的扩展设置。

`tests/script/` 和 `tests/text/` 各按功能分文件，README 放用例索引。脚本函数 `test_COPY_03` 对应 `COPY-03`，无函数的脚本按编号标识检查。文本用例写编号、前提、步骤和预期。两种用例共用每类功能的编号序列。

## 测试时

- **脚本层**按编号做固定检查，例如从系统剪贴板核对完整网址。同一 Chrome 会话中的脚本串行运行，复制操作会写入 macOS 系统剪贴板。
- **AI 层**按文本步骤实测。重要流程有改动或用户反复反馈时，走一遍对应入口。例如脚本核对视频位置，AI 在 Typora 中逐段播放。复制 Grok 译文时，与这次页面显示的译文逐字比对。
- **人类层**处理授权、缺失条件或体验取舍。AI 先给出样本、已尝试的操作和实际结果，由用户决定是否亲测。真实关系或反馈变更按授权执行。

在仓库根目录按编号运行，例如：

```sh
node --test --test-concurrency=1 --test-name-pattern='^\[COPY-03\]' skills/mxga-regression/tests/script/post-copy.test.cjs
```

首屏或滚动性能有改动时，在同一 Chrome 版本、页面和操作下比较前后耗时，按发起方核对新增请求。

脚本异常时，AI 沿同一样本查找第一处差异，保留首次失败和复现条件。修复前后用同一检查，只重跑受影响用例。原样本或等价样本覆盖原触发条件且通过后，才记为修复已验证。功能与测试一起修改时，核对断言仍能识别原错误。前提不足时记下缺项，继续独立用例。

## 测试后

- **结果**按编号记录入口、扩展版本和来源、实际证据及结论，标明通过、失败或未验证。复用同轮证据时注明来源。脚本与 AI 观察有差异时分别记录。其他样本通过时单独报告，未覆盖原触发条件的修复仍记为未验证。
- **清理**在完成、失败或中断时关闭本轮测试标签页，恢复原标签页。记录本轮启动的服务或进程 ID，结束时停止并确认退出，保留原有服务。将临时脚本、截图、日志、导出文件和 Typora 测试文稿移入系统废纸篓，保留交付文件与长期回归资产。
- **维护**在用户明确要求发布时，把本版已验证行为、复现条件和可复用样本补入用例库。已有行为更新原编号，更换样本或执行方式也沿用编号。按需调整冒烟与迭代必测，列明新增、更新、已覆盖和待验证项。
